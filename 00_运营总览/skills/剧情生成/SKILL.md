# Day 连载剧情创作（参考，非门禁）

> **2026-11-09 用户删除五类文案门禁**：三拍顺序、一天一客、逐字接上集原句、
> 零句尾语气词、零阿拉伯数字。`tools/剧本/剧情.py` 现在只查自称口径 / 黑名单 / 笨鱼对白，
> 不再因结构、客人数、语气词或数字退稿。本文下面的「建议」只是写法参考，不是检查项。

先读 `agent.md` 文首覆盖条与第 30 条；已锁定旧集不改。只请求改稿时不配音、不渲染。

## 输入与顺序（可参考）

1. **锁定身份与状态**：读 [references/persona.md](references/persona.md)、上一集台词、当集方向。确认「没做完什么、谁与谁的关系、不能改的事实」。角色大肥鱼不变，只移植魔丸人格。
2. **选一个矛盾**：从上一集留下的具体缺口起戏，也可以直接让多人同台。写不写「找新朋友来帮忙」、请几位客人、梗放在哪一段，都由故事决定。
3. **让梗成为障碍**：朋友/伙伴实际做一次荒唐操作，妨碍的是同一件事，而不是轮流念标签。
4. **主角改变局面**：拆穿不是结尾。让她亲手纠正、重用道具、分配任务，使工作向前一小步；未确认事项继续待确认，不编造真实结果。
5. **收束并交棒**：写清这次完成了什么、还差什么，给下一集一个具体难点。
6. **口播与画面配对**：逐镜写台词行号、主动作、结果、下一镜接法；未配音只做 `measured=false` 的估时，不伪造正式 cue。外部方法依据见 [references/research.md](references/research.md)。

[references/beats.md](references/beats.md) 是 2026-11-05 的 Day12 写法样例与历史笔记，不是现行结构要求。

## 创作入口（不是单独聊天）

```bash
# 不调用模型，检查本轮实际会装载哪些输入，输出可审查的请求包
python3 tools/agent/create_episode.py --day 12 --guest 豆包 --prepare-only
# 已配置 MOWAN_* 时调用模型；只返回待审核候选，不覆盖锁定稿
python3 tools/agent/create_episode.py --day 12 --guest 豆包
```

`--guest` 现在只是自由文本标签，不再限制客人名单或人数。没配置模型就报 `unconfigured`，
mock 不能作为已完成创作的证据。

## 检查与交付

```bash
python3 tools/剧本/剧情.py --prev Day/Day13/Day13配音台词_用户版.txt --txt Day/Day14/Day14配音台词.txt
python3 tools/gate.py --day 14 --stage script
python3 -m unittest discover -s tools/tests -p 'test_*skill.py'
```

脚本只查少量底线；通过不等于人设或故事好看。按 persona.md 的人工问题逐项审读，说明对应台词/动作，再交待确认稿。

**仍然有效的边界**：自称本鲸、笨鱼无新增对白、不改老大真实处境、不报无证据数字
（数字可以写阿拉伯数字，但必须回溯到仓库记录或用户提供的数据）、不把虚构录取说成产品真实行为、
不搬同行形象/配音/点赞关注、不新增生图或换脸、画面红线其余项与零水印照旧。
