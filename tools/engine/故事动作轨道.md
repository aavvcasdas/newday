# 共享故事动作轨道：Day 系列 + Remotion 番外

## 研究和适用范围

- [paint-mv-skills](https://github.com/lintsinghua/paint-mv-skills) `ca8f5f75f186d590e687542b106aa73ceff9133c`：研究了总控、分镜、动画、角色接口、技法、时间、渲染规范及 demo 的共享角色、场景和五章源码。可迁移点：镜头是时间纯函数；脚底点、局部手臂与道具钩子；道具先准备、接触、结果再反应；章节层/动机转场。仓库 MIT，但其按需下载的 PDoomVideo 上游未声明许可；这里没有复制其上游源码或其角色/场景，也没有使用 p5.brush。
- [music-mv](https://github.com/Win-Hao/music-mv) `0088b1422f7f82cdf51b456436a6313127a26d6b`：研究了总流程、角色/分镜/画风/渲染/转场/看片规则、四种风格示例和分析脚本。可迁移点：同一镜头的角色、道具与背景共用时间/相机；相机不等于表演；在手上绑定道具，离手要有明确轨迹；视觉定格和帧差不能替代人工连续看片。它的范例使用 HyperFrames 或逐帧网页，本仓库新歌仍按用户指定使用 Remotion。
- 与用户“保留现有角色、动作、不生成新图片、集中渲染、无尾卡”的指令冲突的示例画风、多次询问/生图、改角色和重渲旧片做法不采用。拍网格、字幕词轴、音源听审必须真实建立；无法仅凭这两个参考解决。

## 新增能力（默认关闭，不影响历史成片）

`story_motion.mjs` 是纯数值模块，按绝对秒采样：

1. `motionPath: [{at,x,y}, ...]` 为演员脚底的分段平滑走位，严格时序；Day 渲染器 `resolveActor()` 执行位置，并在移动区间叠加已有腿骨步态。路径必须与音频/剧情词点一致，停顿须写两个相同位置的关键点；不允许同时写旧 `walk`。没有合法步态的固定 `assetId` 图片不能使用此轨道假装走路。
2. 语义道具 `attach: {actor,anchor,from,to,offset:[dx,dy],release:{duration,to:[x,y]}}` 在持有期间跟随指定演员**已校准**锚点，放开后从释放瞬间的锚点位置平滑到目标，逻辑上无位置跳变。无需释放可省略 `release`；不得与普通 `moves` 混用。角色每个可能姿势都必须有此锚点；图像角色与未校准姿态拒绝绑定。实际画面上的手/纸边遮挡、入手前衔接和接触是否可信仍需看图，不因数学锚点通过就声称真实抓握。
3. `semantic_tracks.mjs` 在真实生产渲染过程中调用共享模块；旧不带轨道的 spec 行为不变。相机、字幕、音频门禁、角色形象和画面红线不放宽。
4. 新歌 Remotion 也直接使用 `sampleMotionPath` 与 `attachedPosition`；走入阶段调用旧的鲸娘步态图集，之后切既有姿态。第六镜的手心逐图集帧仅由肤色区域估算，属于近似，不是 Day 主线的正式接触校准。

## Day12 试验入口

`tools/day12制作/episode.motion_v3.spec.mjs` 复制现有生产 spec，C01 给主角加入实测词点附近的走位，C07 给便签加入与既有 `handR` 校准点绑定的短持有和释放。它仍是 `planning/measured=false` 的**试验方案**，不得走正式生产入口；不覆盖/修改已交付 Day12 v2 视频或其原有 spec。结构检查通过只是字段检查，当前环境缺失四张 Day12 原始姿势缓存，尚未渲染这套新动作，也没有视觉或动态批准。要实际制作时恢复固定素材、重新确认音轨词点和道具连接，再做有声连续检查；不得把技术单测称为 Day12 成片改好。

## 验证与缺口
