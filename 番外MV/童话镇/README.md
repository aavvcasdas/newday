# 《童话镇》立体童话书 MV

MV 线的**参考作品**：40 个镜头、31 句歌词、2 分 22.4 秒。写新 MV 时照着它看。

画面源码来自 `通用模板/来源/remotion-fix-and-mv-recreation.zip`（页面「《童话镇》立体童话书复刻 · Remotion 诊断」里的那支 MV）。
通用模板就是从这份源码里抽出来的；这里留下的是这首歌自己的部分。

## 文件

| 文件 | 说明 |
|---|---|
| `film.json` | 元数据：音源、输出、码率（两遍 4700k） |
| `歌词.srt` | 31 句带时间的歌词（原曲共 50 句，这支 MV 只做到第 31 句） |
| `cues.json` | 卡点：`align` 按原曲实测拍点后生成，不手改 |
| `plan.ts` | 这部片子自己的排镜规则：序章三镜、歌词一句一镜（长句中间再切）、间奏三镜、尾声。沿用源码的写法，所以没有用通用的 `planShots` |
| `project.tsx` | 把上面这些交给模板 |
| `shots/shotsA.ts`、`shots/shotsB.ts` | 40 个镜头 |
| `素材/童话镇.mp4` | 原曲（4 分 09.6 秒） |
| `成片/` | `童话镇.mp4`、`童话镇.srt`、`qa.json`、`童话镇_分镜总览.jpg` |

## 成片

`成片/童话镇.mp4` 是用通用模板从头渲出来的（`npm run film -- full 番外MV/童话镇`），自检记录在 `成片/qa.json`。

| 项 | 值 |
|---|---|
| 画面 | 1920×1080 · 30 fps · 4272 帧 · 2 分 22.4 秒 · H.264 High 4.71 Mbps · BT.709 |
| 声音 | AAC-LC 256 kbps · 48 kHz 立体声 |
| 文件 | 88,535,613 字节（88.5 MB）· sha256 `c6601d9bed23d297863192d83b8982ad5e517cd5e57c653a06752134f40368ea` |
| 水印 / 角标 | 无 |

自检结论（全部无问题）：

- **逐帧**：4272 帧齐全、尺寸一致；没有空画面；没有冻住的画面；40 个切点都真的切了；31 句歌词条都在场。
- **卡点**：按原曲实测（`measured: true`）。歌词起点离最近实拍最多 2 毫秒；歌词镜头的切点比实拍早 1.0–1.9 帧。
- **成片**：音轨相对原曲偏移 0 个采样，相关度 1；整片解码无报错。
- 备注：音源自身有 279 个采样顶到满刻度，原样保留（混音没有加增益）。

`npm run film -- info 番外MV/童话镇` 会核对这份成片是不是当前源码渲的。

**现在它会说「源码在出片之后改过」**：这份成片渲完之后，引擎又改过几次（角色预检、沙漏、字体与文字预检、音源检查），没有重渲。改完之后用现在的源码每个镜头抽一帧，和成片的帧逐像素比过：40 帧里 38 帧完全相同；不同的两帧在第 20 句和第 29 句——飘着的「Z」换了画法，见下面「重构时改了什么」的最后一条。

## 卡点是怎么对的

源码包里没有原曲，卡点直接用歌词文件的时间，节拍按「每句 8 拍」估。这里用 `素材/童话镇.mp4` 的音轨实测（`npm run film -- align`）：

- 全曲拍长 0.42871 秒（139.95 BPM）。每 15 秒一窗复核，最大相位漂移 0.004 秒，节拍全程稳定。
- 31 句歌词的起点各自吸附到最近的实拍：平均移动 0.095 秒，最大 0.198 秒。句序、句数、总长（4272 帧）都不变。
- 31 个歌词镜头的切点落在实拍前 1–2 帧（切点比歌词起点早 2 帧，再取整到帧）；歌词段里角色的踩拍动作和推镜也落在实拍上。
- **没对上拍的地方**：序章和间奏里按时间三等分切的 4 个镜头（I2、I3、N2、N3）；序章和尾声的节拍网格是等分估算，与实拍最多差约 0.1 秒。这是排镜规则决定的，没有动。
- 这是**拍点级**对齐：没有做人声分离，不是逐音节对齐。
- 音轨：原曲从 0 秒对齐混入。成片在第二遍副歌刚起时结束，所以最后 1.5 秒线性淡出。

## 重构时改了什么，没改什么

- **镜头代码几乎没改**：`shots/shotsA.ts`、`shots/shotsB.ts` 与源码包里的逐行比对，不同的只有 import 路径（共 8 行），外加后来改的一处字体（第 18 句书页上的字，见本节最后一条；为它多了 1 行 import）。
- 时间轴、引擎、字幕、出片命令行改用通用模板的（`通用模板/engine`、`通用模板/cli`）。排镜结果与重构前逐镜一致：40 个镜头的起始帧全部相同。
- 抽帧对比过重构前后的同一帧：3D 画面相同；字幕的文字像素有差别（字体现在随合成加载，栅格化不同）。逐帧 md5 因此对不上，这是预期的。
- 角色图集 `cast_atlas.png`：源码包只带了坐标表，没带图。图集的 108 格由仓库已有的像素角色数据重建（`通用模板/cast/`，`npm run atlas:check` 校验逐字节一致）。
- 字体：歌词条和标题用 ZCOOL KuaiLe。第 18 句飞页上的小字「很久很久以前」，源码指定的是楷体；渲染机上没有楷体，画出来的一直是顶替它的 ZCOOL KuaiLe。后来把这一处的字体直接写成模板字体（`shotsA.ts`）——画面不变（抽三帧与成片的帧逐像素相同），只是不再取决于渲染的机器上装没装楷体。

- 第 20 句、第 29 句里飘着的「Z」（贴片 `sprite('zzz')`）：源码是用 `sans-serif` 写的一个字母，长成什么样取决于渲染的机器上装了什么字体。后来改成按轮廓画（`通用模板/engine/kit.ts`），轮廓是照着成片里那个 Z 量的。**这一处画面有细微差别**：形状对得上，边线上的像素不完全一样——抽 7 帧比过，每帧有 0.11%–0.22% 的像素不同，最大差 53 级（满刻度 255），都在 Z 的边线上。仓库里的成片是改之前渲的，里面还是原来的 Z。

## 复现

```bash
npm ci && pip install --user numpy pillow
npm run film -- align 番外MV/童话镇     # 实测拍点 → cues.json（结果应与仓库里的一致）
npm run film -- sheet 番外MV/童话镇     # 分镜总览，约 2 分钟
npm run film -- full  番外MV/童话镇     # 逐帧渲染 → 编码 → 混音 → 自检 → 总览图
```

中间文件（约 1.7 GB 的 PNG 序列）在系统临时目录 `newday-film/tonghuazhen/`，不入库。

## 没做的

- **没有人把成片连续播放着看一遍、听一遍。** 自检只能证明没坏。我做的是：把渲出来的 4272 帧按每秒一格抽成胶片条（143 格），从头到尾看了一遍——40 个镜头的画面和歌词条都对；动作顺不顺、卡点听着准不准，这样看不出来。
- 逐音节同步、响度母带、封面、发布文案，都不在范围内。
- 原曲和角色形象的版权没有核实过，公开发布前需要自己确认（见仓库根目录 README）。
