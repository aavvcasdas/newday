## 来源与改动边界

- `site/`：仓库根目录 `remotion-fix-and-mv-recreation.zip`（sha256 `6349ca43…25731e`）原样解压，21 个文件逐字节一致，没有改任何一行。
- `site/src/mv/assets/cast_atlas.png`：源码包里只有坐标表 `cast_atlas.json`，没带图。图集的 108 格全部来自仓库已有的像素角色数据：
  立绘和头像在 `番外MV/童话镇/src/sprites_data.js`（与《达拉崩吧》是同一份），8 帧步态在同目录的 `walk_cycle_data.js`，调色板取 `px.js`。
  `bake_atlas.mjs` 按坐标表逐格贴回，不缩放不改色；108 格的名字和尺寸全部对得上。
- 其余文件（`entry.tsx`、`render.mjs`、`bake_atlas.mjs`、`align_to_audio.py`、`qa_check.py`）是导出用的外壳，不参与画面内容。

## 按音频对齐是怎么做的

页面没有原曲，卡点直接用仓库 SRT，节拍按「每句 8 拍」估算。这次用根目录 `童话镇.mp4` 的音轨实测：

- 全曲拍长 0.42871 秒（139.95 BPM）。每 15 秒一窗复核，最大相位漂移 0.004 秒，节拍全程稳定。
- 31 句歌词起点各自吸附到最近的实拍：平均移动 0.095 秒，最大 0.198 秒。句序、句数、总长（4272 帧）都不变。
- 结果通过 `starts` / `ends` 两个 props 传给 `MVComp`（它本来就是为对拍留的入口），所以 31 个歌词镜头的切点都落在实拍前 2 帧，
  歌词段里角色的踩拍动作和推镜也落在实拍上。
- 没对上拍的地方：序章和间奏里按时间三等分切的 4 个镜头（I2、I3、N2、N3）；序章和尾声的节拍网格仍是等分估算，与实拍最多差约 0.1 秒。
  这些由时间轴代码的结构决定，没动。
- 这是拍点级对齐。没有做人声分离，不是逐音节对齐。
- 音轨：原曲从 0 秒对齐混入，偏移 0。成片只到第 31 句（原曲共 50 句、4:09.58），第二遍副歌刚起就结束，所以最后 1.5 秒线性淡出。

想出页面原始卡点的版本：`frames` / `mux` 等命令加 `--srt-timing`。

## 渲染环境与页面预览的差别

- **WebGL**：沙盒没有 GPU，用 `gl: 'swangle'`（ANGLE + SwiftShader 软件渲染）。页面说沿用 `render_cli.mjs` 的 `gl: 'angle'` 即可，
  在本沙盒实测建不出 WebGL 上下文，整屏黑。
- **字体**：无头 Chromium 没有中文字体。歌词条与标题用的是 `MVComp` 字体栈的首选 ZCOOL KuaiLe（取自 `番外MV/童话镇-paper-popup/fonts/`）。
  在自己电脑的浏览器里看页面时，没装这款字体会落到系统黑体，所以字形和页面预览不一样。第 18 句飞页上的小字指定的是楷体，这里同样由 ZCOOL KuaiLe 顶替。
- 画面先逐帧出 PNG，再统一编码（x264 两遍 4700 kbps，preset slow，BT.709）。

## 复现

```bash
cd 番外MV/童话镇-remotion3d
npm ci
pip install numpy pillow             # 对齐与自检用
node bake_atlas.mjs --check          # 图集与仓库精灵数据逐字节一致
node render.mjs align                # 实测拍点 → audio_sync.json
node render.mjs full                 # 逐帧渲染 + 编码 + 混音 + 自检
```

2 核软件渲染实测：逐帧 20.5 分钟，编码 6 分钟，逐帧自检 6 分钟。
中间文件（1.7 GB 的 PNG 序列）放在仓库外的 `$MV_WORK`（默认 `/tmp/tonghuazhen-remotion3d-work`），不入库。

## 自检结果（`out/qa.json`）

- 逐帧：4272 帧齐全，全部 1920×1080；没有 WebGL 没画上的空画面；与上一帧完全相同的只有最后 3 帧（片尾已全黑）。
- 成片：视频 4272 帧 / 142.400 秒，音频 142.400 秒；音轨相对原曲的偏移为 0 个采样；整片解码无报错。
- 抽看：从成片里取了 40 个镜头各自的中点帧，画面与歌词条都对应正确。
