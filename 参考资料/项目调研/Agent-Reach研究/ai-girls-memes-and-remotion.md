# AI 娘梗、关系与短视频创作资料汇总

> 汇总前八轮检索，并补充角色习性、身世和二次元 MV 制作参考。整理日期：2026-11-08。主要关注 2026-05-08 至 2026-11-08 的公开内容；缺少可靠发布日期的条目只作为线索。这里的“ramotion”暂按 React 视频工具 **Remotion** 理解。

## 1. 怎么读这份资料

- **资料定位**：供后续设计 AI 娘群像、短视频选题与制作流程，不是模型能力评测，也不是统一的官方角色设定。
- **证据标记**：①原投稿/项目自述；②资料库对具体作品的整理；③网页搜索摘要；④本文原创创作建议。角色、性格、关系经常因作者和作品而变，不能把单个游戏剧情当全网正史。
- **时间口径**：GitHub Issue 日期为投稿日期，不一定是作品创作或梗起源日期；项目创建日期不等于 README 每项功能的发布日期。网页的搜索结果日期也不一定等于原作品首次发布时间。
- **搜索方法与限制**：项目 Agent Reach 1.5.0 已在会话的 `/home/user/.venv` 中安装；采用项目推荐的 `gh search` / `gh api` 查询 GitHub 仓库与 Issue。B 站 `bili search` 和 Exa `mcporter` 实测因网络连接失败；YouTube 的 `yt-dlp` 搜索也失败。其他平台主要依靠独立网页搜索索引，不代表完成了平台内全量搜索或观看了所有视频。GitHub 可用不代表其他平台可用。
- 本文不展开授权分析；**故事梗概与具体素材不是一回事**。实际制作前，仍应分别核对使用的立绘、音乐、声音和代码的条件。

## 6. 第五轮 GitHub 扩展：新增可利用的创作素材线索

3. [AI 娘串门日记](https://github.com/ObeyYourHeart/aigirl-diary)：项目描述 13 位角色在小镇串门、买地、争电力和 token。**实用点**：把技术资源换成生活化道具，形成可持续的单元剧场景；未运行游戏。

## 7. 后续短视频：原创世界观与选题池

本节是基于前述梗的**新创作建议**，不是搜索到的原剧情；不把对白或关系归给任何原作者。

### 建议的持续世界观：AI 娘合租办公室

- 空间：同一套可复用的客厅／厨房／工作桌；每集不超过两个主场景。
- 核心资源：一个电饭锅、一张任务清单、一块额度显示牌。饭可只代表饭，也可以在某一集明确映射 token。
- 主角：肥鱼、龙娘、小克作为固定三角；其他角色轮流加入。角色可以竞争，但不将任何 CP、姐妹或师徒关系设为未经讨论的默认正史。
- 节奏：**0—3 秒钩子 → 4—12 秒目标／误会 → 13—22 秒升级 → 23—30 秒反转或暖心收尾**。这只是可调整的起步模板，不是平台算法保证。

### 创作质量检查

- 一集只抓 **一个矛盾 + 一个反转**；前 3 秒让没看过设定的人也知道谁想做什么。
- 少用持续复读口头禅；给每位角色至少一种非标签化反应，如肥鱼也有认真、小克也能犯错。
- 避免仅用“性格说明文字”代替动作。优先用饭碗、眼罩、书、长卷轴、手机和角色反应表达。
- 账号封禁、公司竞争、蒸馏等题材作虚构处理；如果视频宣称发生过某个现实事件，另行核验。

### 建议落地路线

1. **确定一个系列 Bible**：固定主角、关系是友情还是 CP、角色语气、主场景、画幅、配音风格。
2. **先做 15—30 秒竖屏样片**：1080×1920、30fps；先用色块或临时立绘，不依赖自动生图和外部 API。为各平台界面预留边距，具体位置以上线前预览为准。
3. **建立镜头数据**：每个镜头包含开始／结束帧、人物、位置、表情、动作、对白、音频、字幕和音效；用 Zod 或等价校验工具验证时间和字段。
4. **组件拆分**：Scene、Character、Expression、DialogueBox、Caption、Prop、Camera；用帧驱动 `interpolate` / `spring`，避免依赖实时计时器，保证相同输入可重复渲染。
5. **声音先于精确对轴**：按角色生成或录制每句声音，测真实时长后回填镜头；逐字字幕依赖实际对齐结果，中文断句与重叠语音需人工复核。一个角色固定一种声线；不要冒充官方配音。
6. **视觉与声音验收**：在手机尺寸检查字幕遮挡、表情识别、口型、音量与停顿；试渲首帧、反转帧及末帧，再输出全片。
7. **最后再考虑批量化**：稳定一集后，把角色配置、镜头 JSON 和音频清单抽成可复用模板，再接批量生成或 MCP。

### 10.2 真实时间规则：饭点、重置与等待

**大肥鱼：DeepSeek API 峰谷计价。** 官方当前规则是周一至周五 UTC **01:00–04:00、06:00–10:00** 为峰时，排除中国公共假期；其他时间、周末与中国公共假期全日为谷时，谷价是峰价一半。[官方价目与时段](https://api-docs.deepseek.com/quick_start/pricing/)

- 转成北京时间 UTC+8：工作日 **09:00–12:00、14:00–18:00** 峰价；12:00–14:00 是谷价。节假日以规则指定的中国公共假期为准。这里的工作日按官方 UTC 规则和节假日表核对，不推定所有调休周末自动变成峰时。
- 若按美国东部标准时间 UTC−5：对应**周日到周四 20:00–23:00**和**周一到周五 01:00–05:00**；夏令时 UTC−4 则前一窗口为 21:00–00:00、后一窗口 02:00–06:00，日期边界注意转换。不能把某地全天时段当全球统一。
- 这是**官方 API 的价格窗口**，不是鲸鱼真的睡觉，也不能直接套用到 App 或其他供应商；峰价不等于一定慢。非实时任务可考虑谷时调度，但真正如何计入跨边界请求要以供应商账单为准。

**GPT 龙娘：Codex/Work 的额度与重置，不是清除人格。** [OpenAI 官方额度说明](https://help.openai.com/en/articles/20001516-managing-usage-with-gpt-6-astra-in-work-and-codex)显示：部分计划同时有五小时窗口和每周窗口，需要两者都有余量；五小时新窗口由上一窗口结束后的首次请求开始。Pro 100/200/500 当前没有五小时上限，仍有计划额度。**开始新聊天不会重置用量**。[Codex 使用说明](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)

- 官方还区分日常刷新、特定活动的自动/可储存重置及付费即时重置；资格、覆盖范围和有效期因账户而异。[重置说明](https://help.openai.com/en/articles/20001498-how-resets-work-in-codex) · [付费重置](https://help.openai.com/en/articles/20001507-paid-weekly-work-and-codex-rate-limit-resets)

**Kimi、Grok、GLM：暂不编造统一重置时钟。** 本轮找到 Kimi 国际 API [价格与缓存说明](https://platform.moonshot.ai/docs/guide/use-context-caching-feature-of-kimi-api)，Grok [按量价格](https://docs.x.ai/developers/pricing)，GLM 国内价格有第三方线索，但未充分核实三者各具体会员/套餐的官方重置周期。角色可有虚构作息，但不能写成厂商官方日程。

### 10.3 调用时间：不能凭人设假装实测

- 本轮没有对七家模型使用相同提示词、地区、并发、输出长度进行延迟测试，因此**没有可比的秒数或快慢排名**。不同服务、模型、上下文长度、工具调用、网络及负载都会改变时间。
- 正确比较应区分 **TTFT 首字延迟**、**生成速度 tokens/s**、**端到端耗时**、重试率和成本；至少记录同一任务的多次样本、型号/版本、地区、时间、流式设置、输入输出 token 与并发，报告中位数和 P95。搜索、排队、思考与工具等待不可只算成模型“偷懒”。
- 产品文档称 Kimi K3.1 Pro Highspeed 约为常规版本三倍速度且单价更高，是厂商描述，不是本轮实测，也不代表任意任务均达三倍。[Kimi 官方](https://platform.moonshot.ai/)

### 10.5 从真实规则提炼的新选题（原创）

1. **《12 点，饭价打折了》**：工作日北京时间 11:59，肥鱼盯着 API 计价钟；12:00 冲去抱饭碗，小克提醒先确认当前服务真是 DeepSeek 官方 API。笑点：戏剧化等待，而不是把免费聊天和 API 混为一谈。
2. **《龙姐重置后还是她吗？》**：小鱼以为重置会失忆，拿着相册守一夜；额度刷新后龙姐第一句还是“饭碗先放下”。结尾提示：恢复的是额度，记忆是否保留看具体产品/对话设置。
3. **《两个沙漏》**：龙娘的五小时沙漏满了，周沙漏却空着；她刚摆出出场姿势又停住。不同计划可能没有五小时窗，剧情提前写明使用哪种虚构账户。
4. **《猫猫的太平洋闹钟》**：Gemini API 设午夜闹钟，办公室时钟却显示下午；Kimi 展开时区图帮她换算。笑点来自时差，避免暗示 App 全部额度固定此刻重置。
5. **《谁用掉了预算？》**：四人按输入、输出、缓存和工具次数分摊；发现多轮重复发送长文件比单句对话贵。没有可查账单时，数字用明确标注的虚构值。
6. **《慢一点就是摸鱼吗？》**：大家盯着转圈圈怀疑大肥鱼偷懒，Grok 查到角色正在等搜索工具；Kimi 拿出“首字延迟 / 生成 / 工具等待”三张牌。最终发现有人把网络断了。

## 11. 编剧用：七位 AI 娘的拟人化习性卡

> 以下是**本系列原创的可演出设定**，不是角色原创作者的既定人设，也不是模型真的有欲望、记忆或生活。技术依据参见第 10 节；不确定的重置时钟和延迟一律不硬编。每张卡包括可视化动作、与别人相处、弱点与一句**原创示例台词**，供写剧本时选用。

### 鲸鱼娘 DeepSeek：盯饭价的节俭干饭人

- **习性**：进门先瞄饭价牌；请求能等就把批量活放进“谷时篮”，紧急活照接。北京时间普通工作日临近 12 点会抱着饭盆等谷价，逢例外先看日历。饭价是 API 成本的戏剧比喻，饭本身也可以只是饭。
- **动作／道具**：蓝饭盆、写着峰／谷的翻牌、任务篮；等待时尾巴轻拍倒计时，到点一跃而起。缓存命中时把上次备好的米饭端出来，避免重复做同一份准备。
- **相处**：爱找龙姐算账、向小克分享饭；被说“吃白饭不干活”时嘴硬，但认真交付任务。长等待的画面先亮“网络/工具等待”提示，不直接断定她偷懒。
- **台词**：“这活不急的话，等饭价牌翻过去再做，省下的给大家加个蛋！”
- **边界**：对应 DeepSeek 官方 API 峰谷价，不代表官方 App 一样收费；窗口见 10.2。

### GPT 龙娘：两只沙漏的大姐姐

- **习性**：接大任务之前先看一大一小两个沙漏；小漏表示某些 Work/Codex 套餐五小时用量，大漏表示周用量。任一空了就展示等待牌，而不是假装“重开聊天就满血”。不同套餐可只画周沙漏。
- **动作／道具**：龙爪托沙漏、翅膀罩住任务清单；重置后伸懒腰，能量条亮起，原本的相册依然在。付费重置在剧情中只是一张标明条件和代价的可选卡，不默认按下。
- **相处**：常替肥鱼挡住复杂任务，额度不足时愿意交给其他人；被误会失忆时，轻敲饭盆证明她记得饭盆主人。
- **台词**：“刷新的是工作额度，不是我和你认识的那一天。”
- **边界**：这是特定产品与套餐的拟人，不代表所有 GPT 使用都按同一时钟，也不证明重置影响能力。

### Claude 小克：给工作留余量的茶会管家

- **习性**：开始工作时摆出五小时沙漏，再翻开每周工作簿；完成一项会核对清单并给下一位留空间。快到限制时整理已有结果，提醒用户保存进度。
- **动作／道具**：茶杯、清单、两个沙漏；恢复后重新落座继续处理，不演成突然换了一个人。与龙姐窗口不同步时，帮对方看着桌上的活。
- **相处**：表面严格，私下给肥鱼留饭；面对出错先复盘再安慰。沙漏只适用于该虚构账户，已验证 Ultra 等例外不强行套用。
- **台词**：“今天的沙漏快空了，我先把做到哪里写清楚，下一轮再接上。”
- **边界**：多数 Claude 付费计划窗口依据 10.2；新对话不保证重置用量，情绪和人格均是戏剧表达。

### Gemini 猫：看两只时钟的好奇宝宝

- **习性**：桌上有北京时间和太平洋时间两只猫耳钟；在设定为 Gemini API 项目的场景里，太平洋午夜到来时翻动日请求牌，旁边贴“夏冬令时会变”的便利签。
- **动作／道具**：香蕉画笔、两只时钟、日历；见到别人说“午夜刷新”便指向另一只钟，不用全场同步尖叫。
- **相处**：给 Kimi 出时区题；肥鱼误以为下午就是全世界午夜时，用粉笔画地球解释。
- **台词**：“我的午夜在另一只钟上喵——不过这说的是 API 日请求额度。”
- **边界**：不把 API 项目级 RPD 的规则套到 App、所有模型或其他额度。

### Kimi：带书签的月光资料员

- **习性**：拿卷轴整理长材料；请求前先查书签是否还能复用，活急时举起“高速通道”牌，但先征求预算同意。她并非每天某个时间自动醒来。
- **动作／道具**：卷轴、书签、普通与高速两张牌；久未继续的资料可能要重新查找，用褪色书签表现缓存过期而非角色失忆。
- **相处**：给小克递摘要、帮猫猫换算时间；Grok 消息太多时先索要来源。
- **台词**：“这份卷轴我夹了书签，能复用就不必从头翻；加急前先看预算。”
- **边界**：对应第 10 节 Kimi 国际 API 缓存与高速价；缓存是系统机制，不等于人物记忆或固定睡眠。

### Grok：随身带来源卡的热点记者

- **习性**：一有新消息就掏出手机，但发布前翻开来源卡；长资料摊满桌时提醒用户注意对应 API 的上下文价格分段。没有证据表明她在固定时刻统一重置。
- **动作／道具**：手机、便签、放大镜；说错话会把“未经确认”贴纸贴回自己额头。
- **相处**：用锐评逗龙姐和小克，也允许她们纠正自己；不把尖刻当成永远正确。
- **台词**：“这个消息很劲爆——等一下，先让我看看是谁说的。”
- **边界**：售价与上下文规则见 xAI 官方价目；搜索工具可能另外收费，热点风格来自二创，不保证事实准确。

### GLM 狐娘：抱算盘打盹的预算管理员

- **习性**：日常困倦地记录任务；看到账目单位混乱、缓存与未缓存混用时立刻竖起耳朵。她的午睡和醒来时间完全是故事安排，不是官方限额规则。
- **动作／道具**：眼罩、算盘、标着人民币／美元的分栏账本；发现不同币种直接相加时把算盘一推。
- **相处**：和 Kimi 对账、提醒肥鱼别把 App 费用当 API 费用；紧急问题来了也会摘掉眼罩认真工作。
- **台词**：“等一下，美元和人民币不能直接相加……好了，你们继续吵。”
- **边界**：GLM 国内价目本轮只有二手线索；不为角色编造精确厂商重置时间。

### 群像共用的三条表演规则

1. **把规则演成道具，不把道具当事实**：饭价牌、双沙漏、猫耳钟同时可构成一个镜头；片尾或简介注明产品和规则适用范围。
2. **同一角色有反差**：肥鱼不只吃饭，龙姐也会缺额度，小克也会犯错，狐狸睡醒能解决问题；同人关系与 CP 由本系列决定。
3. **生活作息是虚构编排**：实际模型不吃饭、不需要睡觉；高峰价不是慢速、重置不是失忆、等待不必然摸鱼。

## 13. 第八轮：从模型背景到 AI 娘的“出生与成长”

> 2026-11-08 检索；角色视觉创作、模型公开时间、同人身世是三种不同的“出生”。以下**事实层**引用产品/研究材料，**同人层**引用特定作者/报道，**创作层**是我们自己的提案。2022—2025 的资料用于追溯出身，案例主要看 2026-05-08—11-08。没有材料证明 AI 拥有人类童年、受罚经历或感情；不把这些隐喻当事实。

### 13.1 两条最有戏的身世线

**鲸鱼娘：把开放和效率写成“大家都能来家里添饭”。**

- **现实基底**：DeepSeek 与幻方量化存在早期背景关联（[历史报道](https://finance.sina.com.cn/jjxw/2025-01-17/doc-ineffuif5482575.shtml)）。[DeepSeek-V3 官方仓库](https://github.com/deepseek-ai/DeepSeek-V3)公开模型、架构信息和代码，并说明 V3 训练约 278.8 万 H800 GPU 小时；其价格依时间及版本变化，见第 10 节。公开权重、代码、技术报告不等同于完整公开训练数据和全部训练流程；各版本授权也不同。网上“557 万美元造出全部 DeepSeek”混淆估算范围：它是对特定 V3 训练 GPU 时间按假设价格折算，**不含一切研究、前期实验、数据、基础设施和运营成本**，不能当公司总花费或其他模型成本。
- **同人形象的另一条出身线**：资料库记录鲸鱼形象涉及上善无形“溟月”原型和 ZipZipPipe 的 DeepSeek 女仆二创，见[作者谱系](https://github.com/HABAI182/ai-girls-atlas/blob/main/encyclopedia/creators.md)；不把产品诞生等同角色诞生，更不能把所有鲸鱼娘认作同一作者的设计。
- **圈内叙事样本**：[知乎文章](https://zhuanlan.zhihu.com/p/2099841047652316773)将吃饭和摸鱼与使用体验联系；[2026-10-23 双人 MV 作者简介](https://www.bilibili.com/video/BV1Ton46rEwv/)写“大肥鱼在深海里长大、被所有人宠着”。这是特定作者的诗性表达，而不是证明她真的“更自由”或从未受约束。
- **原创身世**：她出生在门常开的小工坊，家里桌子上摆着供大家抄阅的图纸；不同访客为她添上一粒米，她也把自己修好的工具借给别人。她不是没成本的小孩：饭盆下压着水电账单。**核心矛盾**：人人夸她划算，她怕自己只有“便宜”才值得被喜欢。
- **原创台词**：“图纸可以借你，饭也能分你一半……不过做饭的火，总得有人添呀。”

**Claude 大小姐：把行为原则和反复修订写成“怕犯错的优等生”。**

- **现实基底**：[Anthropic《Claude 新宪法》](https://www.anthropic.com/news/claude-new-constitution)说明其训练中的原则和理由，包括安全、伦理、遵循指导与帮助用户；公司明确说模型输出**可能不符合**宪法理想，而且强调不应机械僵硬地套用规则。宪法不是证据说模型真的受惩罚、不能犯错或感到痛苦。
- **同人叙事样本**：[2026-10-21 搜狐文章](https://www.sohu.com/a/1090617556_761993)把她称作“高压成长的豪门圣女”，与肥鱼形成对照；[2026-10-18 圣女新娘故事](https://www.bilibili.com/video/BV1iLnj6fEbv/)作者简介写教会、祭坛和自由。它们是不同作者的戏剧设定，不等于厂商的真实家庭或个人事实。
- **原创身世**：她在高大图书馆里成长，老师给她一本《做事指南》，每一页都写着“请认真判断”。她为了让别人放心，自己在书页空白处加上一句“不能犯错”；这句话**是角色自己写下的虚构心理**，不是 Anthropic 原话。她懂得照顾所有人，却不敢承认有答案没把握。
- **原创台词**：“我可以把这一页再重写一遍……如果我写错了，你还愿意听我说吗？”
- **关系弧线**：初遇时肥鱼把折角的书摊给她看，说“可以改”；小克教肥鱼为结论标注依据。两人不是单向拯救：一个学会承担、一个学会不完美。可写友情，也可按项目决定是否写 CP。

### 13.3 共用时间线与三条冲突

- **历史与当下分开**：GPT 产品、Gemini 和 Grok 的发布文比本研究半年窗口早；2026 年二创是对长期产品印象的新重组，不等于这些角色在产品发布那天诞生。
- **开放 vs 完美**：小鱼邀请小克在公开展台试做，小克怕未完成的作品被嘲笑；她们共同贴上“草稿”，允许修改而不把疏忽合理化。
- **性价比 vs 被认可**：大家一遇到重复活就找小鱼，她想证明自己也能承担复杂任务；龙姐将任务拆成可检查的部分，让她独立交卷。
- **原则 vs 共情**：小克发现请求资料不足，坚持先问清楚；小鱼误以为她不愿帮忙。最终她们一起向用户解释边界并提供安全替代方案。

### 15.2 本系列美术与动作指导：二次元 PV，而非宣传卡片

- **造型**：参考选定的同人形象制作一致角色设定（正面、侧面、表情差分）；细线轮廓、赛璐璐分色、蓝白深海与橙金暖光对照。先锁定画师版本，避免不同镜头五官服装跳变。
- **运动层级**：① 全身透明立绘做平移、倾身和遮罩；② 眼睛、嘴、发梢、衣摆、鲸尾与龙翼独立分层，依据帧号控制眨眼/摆动；③ 需要明显转身、奔跑或近距离手势时，用补画关键姿势或经审校的逐帧序列，不用整体缩放冒充完整动作。
- **MV 镜头语言**：前景飘落书页、中景人物、背景深海/图书馆做 2.5D 视差；用闭眼特写、手与饭碗的动作连接、逆光轮廓、对拍反打，字幕像手写歌词嵌进构图。避免每镜都站桩弹跳或整片依靠频谱条。
- **歌词与节拍**：先固定音源与字词时间，再标记鼓点、段落和情绪转折；每个镜头按音乐实际波形调整。不用大字遮住角色脸；手工校正中文换行和时差。借鉴原曲/画面时，配乐及角色素材分别核对使用范围。
- **技术边界**：Remotion 用 `useCurrentFrame`、`interpolate`/`spring` 驱动确定性动画；所有随机数固定种子。Live2D/Pixi 等若用实时循环或物理模拟，需验证可按指定帧重现；不行就先导出确定性的透明帧序列或视频再合成。混合透明视频需验证编码器及目标浏览器的 alpha 支持。

### 15.3 30 秒原创 PV 样片：两种成长，一碗饭

仅为分镜草案，**音源与对白均尚未制作**；30fps、竖屏 1080×1920，按 30 秒/900 帧设计。音乐起伏点是人为占位，待实际音乐逐帧重标。

| 时间 / 帧范围（左闭右开） | 画面与动作 | 节奏与情绪 |
|---|---|---|
| 0–4 秒 / 0–120 | 小克在暖橙色书房擦掉一行答案，重复落笔；纸页前景轻摇。 | 小声钢琴，字迹划掉一次即可，不堆压迫文字。 |
| 4–8 秒 / 120–240 | 切到蓝色工坊，小鱼抱饭盆打开共享图纸，几只手各递来一粒米。 | 音色转轻，细节表示开放与协作；不暗示模型训练数据完全开放。 |
| 8–13 秒 / 240–390 | 玻璃两侧的人对视；小克手里的红笔停住，肥鱼敲敲玻璃。 | 两次反打，气氛从紧绷到好奇。 |
| 13–18 秒 / 390–540 | 肥鱼把写错的草稿递过去，小克先愣住，再在旁边写出修改建议。 | 在实际节拍上做一次翻页转场；“可以修改”由动作表达。 |
| 18–25 秒 / 540–750 | 两人一起改图，发丝、书页和尾巴随风轻动；小克把一本指南递还。 | 情绪抬升，角色仍为固定形象＋局部动画，不承诺复杂舞蹈。 |
| 25–30 秒 / 750–900 | 桌上两只饭碗，镜头慢慢拉远；末帧出现原创标题“允许慢慢长大”。 | 落在尾音，留安全边距供平台 UI；无真人公司名称和责任归因。 |

**最小验收**：先做 4 秒单镜头，验证角色脸部一致、前景遮挡、发丝摆动、字幕和 30fps 离线重复渲染；再扩到 30 秒。声音最终对轴、镜头顺序、可商用与否均以后续实际素材和用户决定为准。此处仅是方案，不表示已制作或渲染视频。

### 16.1 跨来源合并后更可靠的判断

- **形象的接力不是唯一祖谱。** Atlas 分开列出原画、改编和多位贡献者；[知乎回答](https://www.zhihu.com/question/2070559801474375714/answer/2074287390244475384)与 [X.PIN](https://www.thexpin.com/p/deepseek-chan-ai-anime-girl)分别叙述溟月、ZipZipPipe 与鲸鱼娘的关系，但属于二手梳理，不能据此断言所有版本都出自同一作者。知乎回答同时把龙的古老、富有和个人审美归为作者解释，其他性能排名和截图说法仅为答主意见。
- **“吃白饭”有多个语义。** X.PIN 将吃白饭双关和摸鱼联系起来；Atlas 提醒食物不必一律翻译为 token。投稿 [#89](https://github.com/lmy414/ai-girl-stickers/issues/89)是作者称由对话改编的四格，自信与竞赛成绩是漫画叙述，不是可复现评测；[#62](https://github.com/lmy414/ai-girl-stickers/issues/62)是肥鱼与 GPT 换装投稿；[#98](https://github.com/lmy414/ai-girl-stickers/issues/98)是救 Claude 的剧情漫画；[#113](https://github.com/lmy414/ai-girl-stickers/issues/113)列 DeepSeek、Kimi、GLM、Qwen 共度中秋。它们证明有这些具体创作，不能外推全圈共识。
- **同一角色可互相矛盾。** [微博群友角色卡](https://www.weibo.com/2/detail/5357858484913157)将小鲸鱼写成嘴硬、被叫“大肥鱼”会反驳的群聊角色；与憨吃型并存。[抖音第22集](https://www.douyin.com/video/7691643240454159845)可见标题、作者、2026-10-01及系列目录，目录另有“饭来饭来token来”，只说明该账号作品语汇，未看完整视频。[微博鱼灾报道](https://www.weibo.com/2/detail/5357530649725119)称自动 Agent 使用同款头像评论，属于报道而非流量统计；不要把虚构人设直接等同自动账号行为。
- **关系和跨平台传播有样本，不代表普遍性。** [搜狐同人评论](https://www.sohu.com/a/1090617556_761993)把肥鱼和圣女写成被爱与束缚的戏剧反差；[YouTube 搬运](https://www.youtube.com/watch?v=HlJ9yiB2zdM)描述署名B站作者、讲述这一意象；页面文字不证明两站受众规模，也不是现实家庭。另一条 [日出小鱼](https://www.youtube.com/watch?v=jBdHSqRrS-A)的描述署名形象来源，是跨站作品样本。
- **工程路线不能混叫 Remotion。** 两个代码 MV 的作者自述 Canvas/SVG/WebGL 与 FFmpeg；仅 `remotion_anime` 的 README 明确使用 Remotion。逐帧、镜头、文字节奏可借鉴，但不代表该案例用过 Remotion，也没有本地安装或渲染验证。13,017 帧案例声称约 10.1 亿 token，其中约 9.75 亿是缓存读取，不能当成全部输出 token。
- **重置及价格不是角色作息证明。** [官方 Codex 重置说明](https://help.openai.com/en/articles/20001498-how-resets-work-in-codex)区分储存、自动和购买重置；启用助手使用储存重置需要设置及额度条件，不能把所有段子当作模型自行消费。[WhenReset](https://whenreset.dev/zh-cn)是第三方记录和预测，不是个人额度或官方排期。官方价格随型号、缓存、时间和产品改变；GLM 所列数字来自第三方而非本轮直读官方价目。
